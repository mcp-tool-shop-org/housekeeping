<h1 align="center">housekeeping</h1>

<p align="center">
  An operational-health warehouse for a GitHub organization.<br>
  One sweep, one SQLite database, findings you can argue with.

एक बार स्कैन करने पर, प्रत्येक रिपॉजिटरी की सीआई स्थिति, खुली समस्याओं और पुल अनुरोधों, रिलीज़, संस्करण टैग, वर्कफ़्लो फ़ाइलों, शाखा सुरक्षा, सुरक्षा अलर्ट, लॉकफ़ाइलों और एक्शन बिलिंग को SQLite में एकत्र किया जाता है, फिर उन सभी का लिखित नियमों के अनुसार ऑडिट किया जाता है।

यह एक साथ पूरी संस्था के लिए उत्तर देता है:

- कौन सी डिफ़ॉल्ट शाखाएँ लाल हैं, और क्या यह एक टूटी हुई मुख्य शाखा या पुरानी इतिहास है?
- कौन से पुल अनुरोध कभी भी मर्ज नहीं हो सकते, क्योंकि एक आवश्यक जाँच अवरुद्ध हो रही है?
- रिपॉजिटरी की अपनी सेटिंग्स कौन से डिप्लॉय को अस्वीकार करती हैं?
- `package.json`, गिट टैग और npm रजिस्ट्री कहाँ अलग हो गए हैं?
- कौन से वर्कफ़्लो एक्शन लागत नियमों का उल्लंघन करते हैं, उनकी लागत क्या थी, और किन कार्यों ने इसे खर्च किया?
- किन रिपॉजिटरी में ऐसी सलाहें हैं जिन्हें GitHub के अपने अलर्ट काउंट में शामिल नहीं किया गया है?

यह एक ऑडिट उपकरण है, न कि एक सुधारक। यह GitHub को पढ़ता है और कुछ भी नहीं बदलता है।

## यह इस तरह से क्यों बनाया गया है

| लेयर | विकल्प | तर्क |
|---|---|---|
| परिवहन | `gh` CLI | इसमें पहले से ही आपका टोकन है। उपकरण कभी भी क्रेडेंशियल संग्रहीत या मांगता नहीं है। |
| संग्रह | GitHub GraphQL, पेज किया गया | एक क्वेरी एक पृष्ठ की रिपॉजिटरी के लिए मेटाडेटा, खुली समस्याएं, खुले पुल अनुरोध, रिलीज़ और फ़ाइल ट्री लौटाती है। एक ऐसा पृष्ठ जो लगातार समय समाप्त हो रहा है, उसे आधा कर दिया जाता है और उसी कर्सर से फिर से पूछा जाता है। |
| एक्शन रन | REST | GraphQL में कोई एक्शन सतह नहीं है। |
| एक्शन लागत | बिलिंग API प्लस प्रति-कार्य अवधि | चालान में बताया गया है कि कौन सी रिपॉजिटरी है; केवल कार्यों में बताया गया है कि कौन सा वर्कफ़्लो। GitHub के `/timing` एंडपॉइंट शून्य लौटाते हैं, इसलिए प्रति-कार्य योग को फिर से बनाया जाता है और फिर चालान के साथ मिलान किया जाता है। |
| रनर दरें | चालान से पढ़ें | एक बिल की गई दर सूची मूल्य से भिन्न हो सकती है, और स्रोत में एक स्थिर मान हर संख्या को गलत बताएगा। |
| भंडारण | अंतर्निहित `node:sqlite` के माध्यम से SQLite | कोई देशी बिल्ड चरण नहीं। |
| सत्य का स्रोत | `data/snapshots/*.json` | कच्चा, तुलना करने योग्य और केवल जोड़ने योग्य। डेटाबेस व्युत्पन्न है: `npm run rebuild` इसे ऑफ़लाइन पुनर्निर्मित करता है। |
| स्कैन लॉग | `data/sweeps.jsonl` | प्रत्येक स्कैन के लिए एक पंक्ति, जिसमें वे स्कैन भी शामिल हैं जो विफल रहे और वे स्कैन जिनमें कुछ भी नया नहीं मिला। |

स्नैपशॉट अपरिवर्तनीय और योज्य होते हैं, इसलिए दो तिथियों के बीच का विचलन `JOIN` है।

## आवश्यकताएँ

- Node.js 22.5 या बाद का संस्करण।
- [GitHub CLI](https://cli.github.com/), साइन इन किया हुआ (`gh auth status`) एक ऐसे खाते के रूप में जो संगठन को पढ़ सकता है। बिलिंग और सुरक्षा अलर्ट पढ़ने के लिए संबंधित एक्सेस की आवश्यकता होती है; इसके बिना स्कैन "मापा नहीं गया" रिकॉर्ड करता है और आगे बढ़ता है। यह कभी भी गुम अनुमति को एक स्वच्छ परिणाम के रूप में रिकॉर्ड नहीं करता है।
- विंडोज या लिनक्स। इसे विंडोज पर विकसित किया गया है और इसके परीक्षण CI में लिनक्स पर चलते हैं। macOS को काम करना चाहिए और इसका परीक्षण नहीं किया गया है।

## उपयोग

```bash
npm install -g @mcptoolshop/housekeeping   # puts `hk` and `hk-mcp` on your path
mkdir warehouse && cd warehouse            # housekeeping keeps its data here
hk refresh your-org                        # collect, load, analyze, write reports/AUDIT-<date>.md
```

सेटिंग्स को बनाए रखने के लिए, उस निर्देशिका में `housekeeping.config.json` रखें (कॉन्फ़िगरेशन देखें); फिर `hk refresh` को किसी तर्क की आवश्यकता नहीं होगी।

या इसे क्लोन से चलाएं, जो अपने डेटा को क्लोन में रखता है:

```bash
git clone https://github.com/mcp-tool-shop-org/housekeeping.git
cd housekeeping
npm install
npm link                 # puts `hk` on your path
cp housekeeping.config.example.json housekeeping.config.json   # then set "org"
hk refresh
```

फिर इसे क्वेरी करें:

```bash
hk summary               # portfolio totals
hk ci                    # repositories whose default branch is red
hk findings              # findings grouped by severity and code
hk health                # per-repository health score, worst first
hk repo <name>           # one repository in full
hk prs                   # every open pull request by age
hk versions              # package.json against git tag against npm
hk actions               # every workflow and its rule flags
hk cost                  # Actions cost, gross and net side by side
hk sql "SELECT ..."      # one read-only statement
hk help                  # every command and flag
```

एक क्लोन में जिसमें `npm link` नहीं है, प्रत्येक `hk <command>` `node src/cli.mjs <command>` होता है।

`npm run rebuild` डेटाबेस और रिपोर्ट को डिस्क पर पहले से मौजूद स्नैपशॉट से पुनर्निर्मित करता है, बिना किसी नेटवर्क एक्सेस के।

एक पूर्ण स्कैन कुछ सौ API कॉल करता है। `refresh` को लूप में न चलाएं।

परिणाम मानक आउटपुट पर जाते हैं; प्रगति और त्रुटियां मानक त्रुटि पर जाती हैं। प्रत्येक त्रुटि एक कोड और एक संकेत प्रिंट करती है। निकास कोड: 0 ठीक, 1 उपयोगकर्ता त्रुटि, 2 रनटाइम त्रुटि, 3 आंशिक (स्कैन समाप्त हो गया, अंतराल के साथ)।

## कॉन्फ़िगरेशन

`housekeeping.config.json`, उस निर्देशिका में जिसमें हाउसकीपिंग काम करता है (नीचे देखें):

```json
{
  "org": "your-org",
  "metaRepos": [".github"]
}
```

- `org` वह संगठन है जिसे स्कैन करना है। `hk refresh <org>` इसे ओवरराइड करता है। दोनों में से किसी के बिना, स्कैन शुरू करने से इनकार कर देगा।
- `metaRepos` वे रिपॉजिटरी हैं जिनमें संगठन डिफ़ॉल्ट, संपत्ति या उपकरण होते हैं, न कि एक शिप किया गया उत्पाद। वे उन निष्कर्षों से छूट प्राप्त हैं जो केवल किसी उत्पाद के लिए समझ में आते हैं: गुम README, LICENSE और समान फ़ाइलें, कोई वर्कफ़्लो नहीं होना और कोई रिलीज़ नहीं होना।

एक गलत फ़ाइल एक त्रुटि है, कभी भी एक मौन डिफ़ॉल्ट नहीं: एक अज्ञात कुंजी, एक गलत प्रकार या टूटा हुआ JSON रन को रोक देता है।

एक क्लोन से चलाएं, हाउसकीपिंग `data/`, `reports/` और कॉन्फ़िगरेशन फ़ाइल को क्लोन में रखता है। एक स्थापित पैकेज के रूप में चलाएं, यह उन्हें उस निर्देशिका में रखता है जिससे आप इसे चलाते हैं, या `HK_HOME` में जब वह सेट हो।

पर्यावरण: `HK_HOME` (जहां डेटा, रिपोर्ट और कॉन्फ़िगरेशन रहते हैं), `HK_CONFIG` (कॉन्फ़िगरेशन पथ), `HK_DB` (डेटाबेस पथ), `HK_LOG` (`silent`, `normal`, `verbose` या `debug`), `HK_COST_REPOS` और `HK_COST_BUDGET` (प्रति-कार्य लागत सीमा), `GH_PATH` (`gh` का पथ)।

## डेटा को निजी रखें

**एक स्कैन जो लिखता है वह संवेदनशील है। `data/` या `reports/` को सार्वजनिक रिपॉजिटरी में कमिट न करें।**

एक स्नैपशॉट निजी रिपॉजिटरी के नाम और विवरण, प्रत्येक खुली सुरक्षा अलर्ट जिसमें वह पैकेज है जिसका वह उल्लेख करता है, वर्कफ़्लो फ़ाइलें और एक्शन बिलिंग रिकॉर्ड करता है। GitHub जानबूझकर एक सार्वजनिक रिपॉजिटरी की सुरक्षा अलर्ट को सभी से छिपा देता है, सिवाय इसके रखरखावकर्ताओं के; एक प्रकाशित स्नैपशॉट उस सूची को दे देगा।

इस रिपॉजिटरी का `.gitignore` `data/`, `reports/` और `housekeeping.config.json` को बाहर करता है। इतिहास को बनाए रखने के लिए, जो स्नैपशॉट का बिंदु है, अपने स्वयं के एक निजी रिपॉजिटरी से उपकरण चलाएं और उन्हें वहां कमिट करें।

## MCP सर्वर

`hk-mcp` (या क्लोन में `npm run mcp`) stdio के माध्यम से डेटाबेस को सेवा प्रदान करता है, इसलिए एक सहायक बिना मल्टी-मेगाबाइट स्नैपशॉट पढ़े प्रश्न पूछ सकता है:

`hk_summary` · `hk_findings` · `hk_ci` · `hk_repo` · `hk_backlog` · `hk_health` · `hk_cost` · `hk_sql` · `hk_schema`

```json
{
  "mcpServers": {
    "housekeeping": { "command": "hk-mcp", "env": { "HK_HOME": "/path/to/warehouse" } }
  }
}
```

`HK_HOME` वह निर्देशिका है जिससे आप डेटा लेते हैं। क्लोन से, इसके बजाय `"command": "node", "args": ["/path/to/housekeeping/src/mcp.mjs"]` का उपयोग करें।

`hk_sql` एक एकल `SELECT` या `WITH` कथन स्वीकार करता है और डेटाबेस को केवल-पढ़ने के लिए खोलता है। एक विफल कॉल एक संरचित त्रुटि लौटाती है, कभी भी स्टैक ट्रेस नहीं।

## निष्कर्ष

नियम `src/analyze.mjs` में रहते हैं। प्रत्येक नियम उस लिखित नियम का हवाला देता है जिसे वह लागू करता है, इसलिए एक निष्कर्ष को एक मानक के खिलाफ तर्क दिया जा सकता है, न कि स्वाद के खिलाफ। इस रिपॉजिटरी में शिप किए गए नियम [`rules/`](rules/) में हैं:

- [`rules/github-actions.md`](rules/github-actions.md): पाथ फ़िल्टर, रनर, मैट्रिक्स आकार, वर्कफ़्लो फ़ाइल सीमा, समवर्तीता।
- [`rules/shipcheck-product-standards.md`](rules/shipcheck-product-standards.md): सीआई को पास होना चाहिए, शिप गेट, संस्करण।
- [`rules/repo-first.md`](rules/repo-first.md): डिफ़ॉल्ट शाखा।
- [`rules/atlas-map.md`](rules/atlas-map.md): प्रत्येक रिपॉजिटरी का एक प्रतिबद्ध मानचित्र, सीआई में जांचा गया।

ये किसी एक संगठन के मानक हैं। यदि आपके मानक अलग हैं, तो नियम फ़ाइल और नियम को बदलें।

नियम उन चीजों को अलग रखने का ध्यान रखते हैं जो समान दिखती हैं, क्योंकि उन्हें एक साथ मिलाने से शोर उत्पन्न होता है:

- **एक लाल डिफ़ॉल्ट शाखा, लाल पुल-अनुरोध शाखा नहीं है।** एक विफल डिपेंडबॉट शाखा बैकलॉग है; डिफ़ॉल्ट शाखा पर एक विफल `push` रन, खराबी है। रन का इवेंट यह तय करता है कि कौन सा।
- **इतिहास खराबी नहीं है।** केवल रिलीज़ के लिए ट्रिगर करने वाले वर्कफ़्लो को स्थानांतरित करने से, इसकी पिछली डिफ़ॉल्ट-शाखा विफलता हमेशा बनी रहती है। एक हटाई गई वर्कफ़्लो अपनी रन को बरकरार रखती है। न तो यह कोई सक्रिय दोष है।
- **एक आवश्यक जांच, जो कुछ भी उत्सर्जित नहीं कर सकती, वह जांच नहीं है जो यहां नहीं चली।** एक कहता है कि आवश्यकता को छोड़ दें; दूसरा कहता है कि ट्रिगर को ठीक करें। दोनों मरम्मत एक-दूसरे का खंडन करते हैं।
- **एक विफल रन, रद्द किया गया रन नहीं है।** `cancel-in-progress` का उद्देश्य पुराने रन को समाप्त करना है, इसलिए रद्द किए गए मिनट आमतौर पर समवर्तीता नियम के काम करने का परिणाम होते हैं।
- **कुल लागत, शुद्ध लागत नहीं है।** GitHub सार्वजनिक रिपॉजिटरी को पूरी कीमत पर मापता है और उन्हें शून्य पर छूट देता है। कुल वास्तविक कंप्यूट है; शुद्ध वास्तविक धन है। उन्हें कभी भी जोड़ा नहीं जाता है।
- **जो मापा नहीं गया, वह साफ नहीं है।** एक रिपॉजिटरी जिसे GitHub स्कैन नहीं कर रहा है, उसमें शून्य अलर्ट होते हैं। एक रिपॉजिटरी जिसकी लागत सीमा तक नहीं पहुंची, उसमें कोई लागत पंक्ति नहीं है। दोनों को अज्ञात के रूप में रिपोर्ट किया जाता है।

गंभीरता एक स्वास्थ्य स्कोर निर्धारित करती है: गंभीर 40, उच्च 15, मध्यम 6, निम्न 2, सूचना 0, जो 100 से घटाया जाता है। स्कोर गुणवत्ता के बजाय ध्यान को रैंक करता है।

[हैंडबुक](https://mcp-tool-shop-org.github.io/housekeeping/handbook/) में प्रत्येक निष्कर्ष, कमांड, त्रुटि कोड और तालिका सूचीबद्ध है।

## सुरक्षा

- **केवल पढ़ने के लिए।** कलेक्टर GraphQL क्वेरी और REST `GET` जारी करता है। यह कभी भी किसी सेटिंग को मर्ज, पुश, रिलीज़, प्रकाशित या संपादित नहीं करता है।
- **कोई क्रेडेंशियल नहीं।** प्रमाणीकरण वह है जो `gh` पहले से ही रखता है। इसके बारे में कुछ भी डिस्क पर नहीं लिखा जाता है।
- **कोई टेलीमेट्री नहीं।** संपर्क किए गए एकमात्र होस्ट GitHub API हैं, `gh` के माध्यम से, और संस्करण और सलाह की जानकारी के लिए npm रजिस्ट्री।
- **यह जो संग्रहीत करता है** वह संवेदनशील भाग है: "डेटा को निजी रखें" देखें।

[SECURITY.md](SECURITY.md) में वर्णित अनुसार किसी भेद्यता की रिपोर्ट करें।

## परीक्षण

```bash
npm test
```

प्रत्येक नियम का दोनों दिशाओं में परीक्षण किया जाता है: वह आकार जो सक्रिय होना चाहिए, और पड़ोसी आकार जो सक्रिय नहीं होना चाहिए। एक अलग सत्यापनकर्ता, अपने स्वयं के परिवहन के माध्यम से, लाइव GitHub से निष्कर्षों का एक नमूना फिर से प्राप्त करता है, और जब कोई डेटाबेस या नेटवर्क नहीं होता है, तो जोर से छोड़ देता है।
